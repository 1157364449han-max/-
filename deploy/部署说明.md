## 访问口令维护约定

发布和升级必须保留服务端已经配置的访问口令。除非项目所有者明确要求更换，不运行口令重置、随机生成或轮换操作。口令只在私有服务端配置中维护，不写进网页、题库或更新包；模型 API 凭证的轮换不应改变用户访问口令。

### 0.27.0 阿里云百炼独立推理后端（待开通真实服务）

此节记录此前候选方案，不代表已开通百炼服务。当前 `render.yaml` 使用现有 DeepSeek Chat Completions 配置，保留原访问口令，不自动生成或轮换口令；Render 付费方案未开通。若今后改用百炼，API Key 与接入地址须属于同一地域，凭证仅存服务端；必须通过真实题目请求验收，不能只看模型列表检测。

Render 免费实例可能休眠，冷启动会带来等待。百炼免费额度与限额应以账号控制台为准；额度用尽且开启用完即停后可能返回 403。蓝图适合个人试运行，不代表已满足大量公众用户的可用性要求。Render 和阿里云账号、服务条款、验证以及 API 密钥的生成必须由账号拥有者完成；助手不能无凭据代建该云资源。

`chat-completions` 服务端适配器按兼容协议的 SSE 输出解析千问响应；不能把协议模拟测试等同于真实模型能力验收。

在独立云平台部署本仓库 Dockerfile，由平台提供 HTTPS。模型推理由外部 API 承担，无须该 Web 容器安装 GPU 或下载模型。设置服务端环境变量：

```text
DONGJIEXI_CLOUD=1
DONGJIEXI_INFERENCE_PROVIDER=chat-completions
DONGJIEXI_MODEL_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
DONGJIEXI_MODEL_API_KEY=仅在云平台Secret中填写真实密钥
DONGJIEXI_MODEL_ID=qwen3.5-plus
DONGJIEXI_ACCESS_KEY=独立的访问口令而非模型密钥
DONGJIEXI_ALLOWED_ORIGINS=https://dongjiexi.github.io
DONGJIEXI_MAX_CONCURRENT=2
DONGJIEXI_JOBS_PER_10_MINUTES=4
```

若设置 `DONGJIEXI_ALLOWED_MODELS`，必须包含同一个模型 ID；未设置则默认只允许 `DONGJIEXI_MODEL_ID`。密钥不得写进 dist、仓库变量或用户输入框。`ALLOWED_ORIGINS` 是来源（不含 Pages 的 /-/ 路径）。使用 Compose 时通过 `docker compose --env-file deploy/cloud.env up -d --build` 读取环境文件。

云端 `/api/health` 与登录、模型列表、完整题目、取消、429、验证结果均验收后，才把公开 API 地址写入仓库变量 `DONGJIEXI_API_BASE` 并重新发布前端。当前没有云账号或 API 凭据，不要设置假的地址让网站声称云端已就绪。

限流与并发：每进程云端默认 2 个任务，上限 8；满载直接返回 HTTP 429 / Retry-After，不建立无限队列。默认“快速解题”只发一次主推理，省去串行补答与图形补建；用户选“深入推导”时保留最多两次遗漏小问补答及一次图形补建。推理有时间/输出长度限制。原有任务归属、会话、取消与请求限流保留。当前任务状态与会话存内存，正式多副本部署前需要共享任务/配额存储或粘性路由；当前应先单副本小规模验收。额度耗尽不会自动下载模型或转发到用户电脑。

本机选项：不设置 `DONGJIEXI_INFERENCE_PROVIDER` 时继续使用原有 Ollama、本机模型安装脚本与下载入口。本机一次运行一个模型任务，避免资源争抢。公开 HTTPS 网页不直接访问 localhost；用户主动打开已安装的本机版处理题目。它不等于已经完成通用免环境桌面安装包，也不适用于声称手机能运行桌面模型。

云端适配器同时支持文字 AI 解题与 PNG、JPEG、WebP 题图识别；题图只有用户主动勾选云端选项时才上传。模型列表可访问不代表已获配额或实际推理必定可用；必须另外做真实请求验收。

- 手机和电脑浏览器使用同一份中文 PWA，不需要额外运行环境，也不依赖维护者电脑开机。
- 未设置 API 时，浏览器内置已覆盖题型的解题、建模与画板仍可使用；图片可由浏览器本地 OCR 识别，但公式准确度有限。开放题 AI 增强不可用，未覆盖题型不伪装成已解答。
- `deploy/build_release.py` 生成 `runtime-config.js`，默认 `deployment=web`、`apiEnabled=false`，不会把本机服务地址带到公开网页。
- 当前发布目标仓库为 `dongjiexi/-`。首次部署成功前，不应把预期 URL 说成已经可用的网址。

## 自动更新

`version.json`、`dist/app-version.json`、`dist/service-worker.js` 和页面资源版本必须一致。推送主分支后，GitHub Pages 工作流发布同一份 `dist/`。手机 PWA 在打开、恢复前台以及每 30 分钟检查更新；发现新版后提示用户确认，再一次性刷新全部资源。

同一个工作流还会从该提交生成 `downloads/dongjiexi-v版本号.zip`、计算 SHA-256，并写出 `update-manifest.json`。桌面“检查更新.bat”读取这份 HTTPS 清单并校验哈希后原地升级；网页与桌面包不会分别手工修改。Pages 尚未首次成功发布前，该在线地址会暂时不可用，仍可使用本地 ZIP 更新。

## GitHub Pages

1. 本应用可作为独立仓库根目录，也支持已有仓库的 `apps/dongjiexi/` 子目录布局。
2. 工作流 `.github/workflows/deploy-dongjiexi.yml` 会运行全部 Python、几何、浏览器契约与实际 Chromium 回归；任一步失败不会发布。
3. 仓库必须符合 GitHub Pages 托管资格，且 Settings → Pages 的 Source 为 GitHub Actions。默认工作流令牌不能代替管理员首次开启 Pages；权限不足会明确失败。
4. 未设置 `DONGJIEXI_API_BASE` 时发布独立静态版。确需云增强时才在 Actions variable 填独立公开 HTTPS API 地址，不能填本机、局域网地址或密钥。
5. 同次构建生成网页 ZIP、桌面 ZIP、SHA-256 和更新清单。测试截图和发布包会保存在 Actions artifacts，便于失败时检查。

当前独立仓库的预期网址是 `https://dongjiexi.github.io/-/`。须在工作流部署成功后，另行检查首页、版本 JSON、离线缓存及更新包链接，才算完成上线。

本地复现发布构建（输出目录必须不存在或为空）：

```text
python deploy/build_release.py --output _release --site-base https://dongjiexi.github.io/-
```

`_release/site/` 可部署到静态 HTTPS 托管服务。构建器检查版本一致性，拒绝覆盖已有产物、外部符号链接、未允许的网页文件和不安全发布地址。桌面包仅包含明确列出的源码、网页和测试，不包含环境密钥、用户题本或本机模型。

## 可选云端 API（不是静态站点的必需条件）

Python 服务应使用 `Dockerfile` 部署在独立云端 HTTPS 域名；服务器通过 `DONGJIEXI_OLLAMA_URL` 连接受保护的推理服务。模型令牌和 `DONGJIEXI_ACCESS_KEY` 只存放在云平台加密环境变量中，绝不能写入前端或仓库。前端与 API 分域时，`DONGJIEXI_ALLOWED_ORIGINS` 必须列出完整前端 HTTPS 来源，不得使用 `*`。

构建并运行：

```text
docker build -t dongjiexi:0.23.0 .
docker run --rm -p 8765:8765 --env-file deploy/cloud.env dongjiexi:0.23.0
```

程序在云端模式下默认拒绝未授权调用；访问口令换取短期内存会话，并按会话限制解题次数、查询频率、模型白名单和任务有效期。生产环境仍必须在反向代理或云平台开启 HTTPS、第二层速率限制、运行日志脱敏和费用告警。访问口令适合个人/小范围部署；面向公众开放前应接入正式用户账号或学校统一身份系统。
