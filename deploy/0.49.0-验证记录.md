# 0.49.0 DeepSeek 直接识图验证

## 原因与改造

旧公开 Worker 强制 `vision:false` 且只收文字，图片识题主要使用普通 Tesseract OCR。新版本按 DeepSeek 当前官方 Vision 文档接入 `deepseek-flash` 的真实 `image_url` 图片输入，使用 `detail:original`，不把 OCR 文字冒充图片识别。文字解题的模型选择与 Flash 识图独立。

- `dist/recognition-contract.mjs`：独立转录 JSON 契约与禁止猜题提示，原位模糊占位、完整小问、分数/向量/上下标；严格输入大小和图片签名。
- `deploy/cloudflare/worker.mjs`：`/api/recognize` 受原会话、并发、共享配额保护，固定 DeepSeek 上游，无网页密钥，无任意图片 URL。图片上限 2 MiB，请求上限 3 MiB；文字接口仍 64 KiB。
- `dist/runtime.js`、`dist/learning-ui.js`：完整 SSE 才接收题面，识图与解题契约分开；不自动重试/解题，换图和失败保留题稿。云端未授权不静默改用普通 OCR。
- `dist/index.html`、`dist/learning-ui.css`：点击才上传，原图和编辑框/公式预览对照；模糊处需人工补正与确认；手机单列滚动，浏览器 OCR 可选。
- 版本、PWA 缓存、桌面更新器与 CI 同步，公开解题仍只显示云端。口令“董老师666”、每天 50 次、每客户端 10 分钟 4 次、并发 2 未改。识图属于计费模型请求，并非免费无限使用。

## 验证

- 207 项 Python 回归通过（1 项平台权限测试跳过）；26 组 Node 测试通过。
- 52 组浏览器回归通过；新增真实公开云端页面形态的视觉协议测试，覆盖原图上传时机、Flash/Pro 分离、全部小问、向量/分数 KaTeX、手机宽度、核对门禁与不完整流不覆盖题稿。
- 真正的云端模型实测：用户原始照片 `954e30686bdb05871c37941efa54d627.jpg`（未把参考转录交给模型），通过实际 Worker→DeepSeek 的一次请求约 5.434 秒；正确读出 A(-1,0)、B(1,2)、PM·PN 向量、二面角 M-OA-N 的 2π/3 和全部 3 问，未自动写入或解题。此时前端为候选静态文件，后端是真实部署服务，非模拟回复；正式上线后另行验证。
- 普通 Node HTTP 环境一次连通检查失败，不算模型质量结果；浏览器实际云端测试通过。协议回归不代表所有数学照片、手写字或遮挡条件都能准确识别。

## 剩余边界

识图仍可能看错；强反光、遮挡、模糊手写和图形隐含关系仍需核对。当前每次识别一道题、单张图，不增加按题号自动分割或云端图片存档；下一阶段可根据真实失误样本评估裁剪、旋转和多图拼接，而不是通过题库猜补内容。
