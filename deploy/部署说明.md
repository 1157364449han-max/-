# 董解析 Web / 手机部署

## 默认发布：独立静态 Web / PWA

- 手机和电脑浏览器使用同一份中文 PWA，不需要额外运行环境，也不依赖维护者电脑开机。
- 未设置 API 时，浏览器内置已覆盖题型的解题、建模与画板仍可使用，不仅是画图。图片识别和开放题 AI 增强不可用，未覆盖题型不伪装成已解答。
- `deploy/build_release.py` 生成 `runtime-config.js`，默认 `deployment=web`、`apiEnabled=false`，不会把本机服务地址带到公开网页。
- 当前发布目标仓库为 `1157364449han-max/-`。首次部署成功前，不应把预期 URL 说成已经可用的网址。

## 自动更新

`version.json`、`dist/app-version.json`、`dist/service-worker.js` 和页面资源版本必须一致。推送主分支后，GitHub Pages 工作流发布同一份 `dist/`。手机 PWA 在打开、恢复前台以及每 30 分钟检查更新；发现新版后提示用户确认，再一次性刷新全部资源。

同一个工作流还会从该提交生成 `downloads/dongjiexi-v版本号.zip`、计算 SHA-256，并写出 `update-manifest.json`。桌面“检查更新.bat”读取这份 HTTPS 清单并校验哈希后原地升级；网页与桌面包不会分别手工修改。Pages 尚未首次成功发布前，该在线地址会暂时不可用，仍可使用本地 ZIP 更新。

## GitHub Pages

1. 本应用可作为独立仓库根目录，也支持已有仓库的 `apps/dongjiexi/` 子目录布局。
2. 工作流 `.github/workflows/deploy-dongjiexi.yml` 会运行全部 Python、几何、浏览器契约与实际 Chromium 回归；任一步失败不会发布。
3. 仓库必须符合 GitHub Pages 托管资格，且 Settings → Pages 的 Source 为 GitHub Actions。默认工作流令牌不能代替管理员首次开启 Pages；权限不足会明确失败。
4. 未设置 `DONGJIEXI_API_BASE` 时发布独立静态版。确需云增强时才在 Actions variable 填独立公开 HTTPS API 地址，不能填本机、局域网地址或密钥。
5. 同次构建生成网页 ZIP、桌面 ZIP、SHA-256 和更新清单。测试截图和发布包会保存在 Actions artifacts，便于失败时检查。

当前独立仓库的预期网址是 `https://1157364449han-max.github.io/-/`。须在工作流部署成功后，另行检查首页、版本 JSON、离线缓存及更新包链接，才算完成上线。

本地复现发布构建（输出目录必须不存在或为空）：

```text
python deploy/build_release.py --output _release --site-base https://1157364449han-max.github.io/-
```

`_release/site/` 可部署到静态 HTTPS 托管服务。构建器检查版本一致性，拒绝覆盖已有产物、外部符号链接、未允许的网页文件和不安全发布地址。桌面包仅包含明确列出的源码、网页和测试，不包含环境密钥、用户题本或本机模型。

## 可选云端 API（不是静态站点的必需条件）

Python 服务应使用 `Dockerfile` 部署在独立云端 HTTPS 域名；服务器通过 `DONGJIEXI_OLLAMA_URL` 连接受保护的推理服务。模型令牌和 `DONGJIEXI_ACCESS_KEY` 只存放在云平台加密环境变量中，绝不能写入前端或仓库。前端与 API 分域时，`DONGJIEXI_ALLOWED_ORIGINS` 必须列出完整前端 HTTPS 来源，不得使用 `*`。

构建并运行：

```text
docker build -t dongjiexi:0.21.1 .
docker run --rm -p 8765:8765 --env-file deploy/cloud.env dongjiexi:0.21.1
```

程序在云端模式下默认拒绝未授权调用；访问口令换取短期内存会话，并按会话限制解题次数、查询频率、模型白名单和任务有效期。生产环境仍必须在反向代理或云平台开启 HTTPS、第二层速率限制、运行日志脱敏和费用告警。访问口令适合个人/小范围部署；面向公众开放前应接入正式用户账号或学校统一身份系统。
